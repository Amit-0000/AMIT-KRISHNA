VoiceGuard is a well-structured ML research project repurposed as a
production-facing tool. The ML core is solid — clean architecture, correct
implementations of LCNN and RawNet2, good experiment tooling, and a
competitive 7.07% EER against the published baseline. The documentation is
thorough and the codebase reflects thoughtful engineering.

However, the transition from research to production has left a set of
critical and high-severity gaps that would prevent responsible deployment:

PRODUCTION BLOCKERS (must fix before any public exposure):
  - Unsafe model deserialization in 6 locations (RCE via crafted .pt file)
  - No authentication or rate limiting on the inference API (free compute abuse + DoS)
  - Full HTTP body buffered before size check (memory exhaustion DoS)
  - Model checkpoint loaded without hash verification (supply-chain attack path)
  - CI/CD pipeline contains a TODO placeholder repo_id that will cause
    push failure — or worse, overwrite the original author's HF Space

SIGNIFICANT GAPS:
  - Zero test coverage (no unit, integration, or e2e tests)
  - Massive code duplication between app.py and demo/app.py (~250 lines)
  - Missing runtime dependency (pandas) not declared in pyproject.toml
  - Python version stated in 4 places with 3 different values
  - Matplotlib figures not closed after each inference (memory leak under load)
  - GradCAM always targets spoof class regardless of actual prediction (UX bug)

The project is production-ready from an ML correctness standpoint but
requires 2–4 engineering days of hardening before any public deployment.

Overall Health Score: 58 / 100

Project Purpose
---------------
Binary audio classification system: determines whether a speech clip is
real human speech ("bonafide") or AI-generated ("spoof"). Trained on the
ASVspoof 2019 Logical Access benchmark, achieving 7.07% EER. Intended as
a portfolio project demonstrating ML, deployment, and explainability skills.

Architecture Overview
---------------------
Two independent deployment surfaces share a single ML inference core:

  Surface A — HuggingFace Spaces (Gradio)
    app.py → src/inference/predict.py → LCNN → result + GradCAM

  Surface B — Docker Container (FastAPI REST API)
    POST /predict → api/main.py → src/inference/predict.py → LCNN → JSON

  Shared ML Core
    src/data/     → audio loading, protocol parsing, transforms
    src/models/   → LCNN, RawNet2, ensemble fusion
    src/training/ → trainer loop, loss, TensorBoard
    src/evaluation/ → EER computation
    src/explainability/ → GradCAM

Major Components
----------------
1. LCNN  — Light CNN with Max-Feature-Map activation. 699,938 params.
           Input: log mel-spectrogram [B, 1, 128, 251]
           Output: logits [B, 2]
2. RawNet2 — End-to-end model with SincConv + ResBlocks + GRU. 4.9M params.
           Input: raw waveform [B, 1, 64000]
           Output: logits [B, 2]
3. GradCAM — Hooks into LCNN features[9] to produce heatmaps.
4. FastAPI  — Single endpoint /predict, single worker, no auth.
5. Gradio   — Blocks-based UI with custom CSS dark theme.

STRENGTHS
---------
- Clean layered separation: data → models → inference → API/UI
- FastAPI lifespan hook correctly loads model once at startup
- Config-driven training (YAML) with sensible defaults
- GradCAM cleanly abstracted into its own class with forward/backward hooks
- Trainer class follows single-responsibility principle
- EER computation correctly isolated in its own module

WEAKNESSES
----------

A3-01: Massive Code Duplication — app.py vs demo/app.py
  The two Gradio app files are 90%+ identical. Both contain:
    - Identical 200+ line _CSS block
    - Identical _HEAD block
    - Identical run_inference() function (only docstring differs)
    - Identical gr.Blocks layout
    - Same _HF_REPO constant
  This means any styling change requires two edits and any logic fix
  requires two edits — a violation of DRY at the file level.
  Files: app.py:1-329, demo/app.py:1-273

A3-02: GradCAM Always Targets Spoof Class Regardless of Prediction
  In both app.py and demo/app.py, GradCAM is always called with
  target_class=1 (spoof) even when the model predicts bonafide.
  Files: app.py:50, demo/app.py:52
  Effect: For a bonafide audio clip, the heatmap shows "what the model
  would attend to if classifying as spoof" rather than the features
  supporting the actual bonafide prediction. This is semantically
  incorrect and potentially misleading to users.

A3-03: Model Initialization at Module Level (Blocking Import)
  In app.py lines 25-37:
    CHECKPOINT = Path(hf_hub_download(...))  # network call at import time
    device = get_device()
    model = load_model(CHECKPOINT, device)   # model load at import time
  These execute during Python import, not inside a lifecycle hook.
  Any failure (network down, missing checkpoint, corrupt file) crashes
  the process at startup with no structured error message, no retry,
  and no graceful degradation.
  By contrast, api/main.py correctly uses a lifespan hook.
  Files: app.py:25-37, demo/app.py:24-38

A3-04: Configs Not Used at Inference Time
  configs/lcnn.yaml contains model hyperparameters (batch_size, lr,
  scheduler, etc.) but nothing in the inference path reads these files.
  The production model (LCNN()) uses hardcoded architecture constants.
  The YAML files only affect training scripts. This means a training-time
  config change is not automatically reflected in inference, creating a
  potential drift between training and serving configurations.
  Files: configs/lcnn.yaml, src/inference/predict.py

A3-05: get_device() Logic Duplicated 4 Times
  The same device detection function is independently defined in:
    app.py:28-31       (no MPS branch)
    api/main.py:17-23  (has MPS branch)
    demo/app.py:28-33  (has MPS branch)
    scripts/train.py:20-26 (has MPS branch)
  The app.py version is missing the MPS branch, silently falling back
  to CPU on Apple Silicon — a performance regression for that platform.
  Files: app.py:28-31

A3-06: PredictionResponse.label Has No Enum Validation
  api/schemas.py defines label as plain str with no validation constraint.
  The valid values are "bonafide" and "spoof" but nothing enforces this
  in the schema. A future modification to predict.py that returns a
  different string would silently pass schema validation.
  Files: api/schemas.py:10, src/inference/predict.py:7

A3-07: No tests/ Directory
  README.md references a tests/ directory in the project structure but
  no such directory exists. There are zero automated tests.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

STRENGTHS
---------
- Concise, well-named functions and classes throughout
- Type hints used consistently (Python 3.10+ union syntax)
- Docstrings on all public functions
- LCNN and RawNet2 implementations have inline shape annotations on
  every layer — excellent for maintainability
- ConvBlock correctly documents the MFM channel doubling behavior
- trainer.py correctly identifies the NaN behavior (x != x), even if
  math.isnan() would be more idiomatic

WEAKNESSES
----------

CQ-01: Incorrect Comment in transforms.py
  transforms.py line 42 says: `return mel  # [1, 128, 313]`
  The actual output shape is [1, 128, 251] for 64000-sample input at
  hop_length=256. This is confirmed by:
    - predict.py:24 comment: `# [1, 1, 128, 251]`
    - LCNN classifier Linear(32 * 8 * 15, 160) — only valid for width=251
      (after 4x MaxPool2d(2,2): 251 → 125 → 62 → 31 → 15)
  The 313 figure corresponds to 80000 samples (5 seconds), not 64000.
  Files: src/data/transforms.py:42

CQ-02: Non-Idiomatic NaN Check
  trainer.py line 94: `if dev_eer != dev_eer:`
  While this is valid Python (NaN != NaN), the standard idiom is
  `import math; if math.isnan(dev_eer):` which is immediately readable.
  Files: src/training/trainer.py:94

CQ-03: fuse_scores() Silent Failure Path
  ensemble.py lines 48-62: If fusion="learned" is passed but lr_model
  is None, the function raises ValueError. But the default parameter is
  lr_model=None, meaning any call with fusion="learned" and no lr_model
  will fail at runtime rather than at function definition.
  A better signature would make lr_model required when fusion="learned"
  or use overloads.
  Files: src/models/ensemble.py:43-62

CQ-04: Matplotlib Figure Memory Leak
  In both app.py:run_inference() and demo/app.py:run_inference(),
  plt.tight_layout() is called and the figure is returned. There is no
  plt.close(fig) call. In Gradio's execution model, this means each
  inference request accumulates a matplotlib figure in memory.
  Under any non-trivial load, this will cause memory to grow unboundedly.
  Note: gradcam.py:visualize() DOES correctly call plt.close() but
  the inference handlers in app.py/demo/app.py do not.
  Files: app.py:93, demo/app.py:95

CQ-05: Large Inline CSS Blocks in Python Files
  Both app.py and demo/app.py embed a ~200-line CSS string directly in
  Python source. This makes the Python files harder to read and prevents
  CSS tooling (linters, formatters) from working on the styles.
  Stylesheets should be extracted to a .css file and loaded at runtime
  (with Gradio's css= parameter accepting a file path in some versions)
  or at minimum to a shared Python module.
  Files: app.py:98-289, demo/app.py:101-237

CQ-06: Hardcoded Evaluation Results in evaluate_ensemble.py
  evaluate_ensemble.py lines 76-82 contain hardcoded per-attack EER
  values as Python dicts rather than reading them from stored evaluation
  artifacts. This creates a maintenance burden — if models are retrained,
  these numbers must be manually updated.
  Files: scripts/evaluate_ensemble.py:76-82

CQ-07: Missing __all__ in All __init__.py Files
  All src/__init__.py files are empty, providing no public API surface
  and no control over what `from src.models import *` would export.
  Files: src/__init__.py, src/models/__init__.py, all module __init__.py

CQ-08: No Input Normalization Documentation
  The LCNN and RawNet2 training pipeline applies log-mel transformation
  and SpecAugment, but there is no normalization (mean subtraction,
  per-feature standardization). While this may be intentional, it is
  undocumented. Inference-time inputs could have very different amplitude
  characteristics than training data, affecting confidence scores.

Severity: HIGH
Category: Unsafe Deserialization / RCE
Location: src/inference/predict.py:13
          scripts/evaluate.py:40
          scripts/evaluate_rawnet2.py:38
          scripts/evaluate_ensemble.py:19
          scripts/train_rawnet2.py:62

Description:
  torch.load() is called without weights_only=True at 6 locations.
  PyTorch uses pickle internally, allowing arbitrary code execution via
  a crafted .pt file.
Evidence:
  model.load_state_dict(torch.load(checkpoint_path, map_location=device))
  All 6 occurrences follow this pattern with no weights_only argument.
Impact:
  Full RCE on inference server if checkpoint is replaced by an attacker.
  Combined with F-05 (no hash check after HF download), the attack surface
  extends to supply-chain compromise.
Recommendation:
  torch.load(checkpoint_path, map_location=device, weights_only=True)
  Apply to all 6 locations. This is the PyTorch-recommended default since 2.4+.
Estimated Effort: Small (5 minutes — 6 one-line changes)

Severity: HIGH
Category: Denial of Service / Input Validation
Location: api/main.py:52-54
Description:
  The file size gate fires after await audio_file.read() has already
  loaded the entire request body into server memory. An attacker can
  send a 1GB+ multipart body; the server allocates it before rejecting.
Evidence:

  requests. Single-worker Uvicorn is particularly vulnerable.
Recommendation:

  streaming chunked read with a running total check.

Severity: MEDIUM
Category: Concurrency / Thread Safety
Location: app.py:34-36, api/main.py:50-71
Description:
  The LCNN model is shared across concurrent async requests with no
  mutex. app.py uses a global module-level model; api/main.py shares
  via app.state.model. PyTorch's model.eval() is generally safe for
  concurrent reads on CPU, but is NOT safe under MPS (Apple Silicon)
  which is one of the target deployment devices. Additionally, GradCAM
  in app.py calls model.zero_grad() and score.backward() — these mutate
  model state and are definitely not safe under concurrent access.
Evidence:
  model = load_model(CHECKPOINT, device)     # app.py:35, module-level
  gradcam = GradCAM(model, device)           # app.py:36, same model ref
  GradCAM.compute() calls model.zero_grad() and score.backward()
Impact:
  Concurrent Gradio users could trigger simultaneous backward passes on
  the same model, causing corrupted gradient state, incorrect heatmaps,
  or crashes under MPS.
Recommendation:
  Use asyncio.Lock() around the backward pass in GradCAM.compute(), or
  maintain a separate model instance per request for GradCAM calls.
Estimated Effort: Small (45 minutes)

STRENGTHS
---------

- Correct use of lifespan hook for model loading
- Appropriate HTTP status codes (400, 413, 500)
- File extension allowlist uses a set (O(1) lookup)
- UploadFile with File(...) is idiomatic FastAPI

WEAKNESSES
----------

API-01: No API Versioning
  /predict has no version prefix (/v1/predict). Any breaking change to
  the response schema will immediately affect all existing clients.
  Recommendation: prefix routes with /v1/ from the start.

API-02: Unstructured ML Errors Return 500
  If predict() raises an exception (e.g., audio too short, corrupt file
  that passes extension check), FastAPI returns an unstructured 500 error.
  Clients receive a generic internal server error with no actionable
  information. Add a try/except around predict() that returns 422
  Unprocessable Entity with a descriptive message.

API-03: /health Does Not Reflect Model State
  See Reliability finding above. Health endpoint is always healthy.

API-04: No Request/Response Logging or Correlation IDs
  No request IDs, no timing headers, no access logging. Impossible to
  correlate client reports with server logs.

API-05: label Field Not Constrained in Response Model
  PredictionResponse.label is str. Should be Literal["bonafide", "spoof"]
  or an Enum to make the contract explicit and self-documenting.

API-06: confidence Has No Calibration Warning
  The model's confidence score is not calibrated (no temperature scaling
  or Platt scaling was performed). Values near 0.5 are genuinely uncertain
  but the API returns them without any uncertainty indicator. Consider
  adding an "uncertain" flag or confidence_threshold field.

UI-01: GradCAM Always Shows Spoof Attention (Incorrect for Bonafide)

  unfamiliar with probability would benefit from a percentage display

  on A17 attacks means a 97% "spoof" confidence could still be wrong —
  no uncertainty disclaimer is shown.

UI-07: demo/app.py vs app.py Are Duplicate Deployment Targets
  Two near-identical files serve no technical purpose. demo/app.py adds
  only `server_port=7860, share=False` to the launch() call. This should
  be a single file with launch() parameters configurable via env vars.
