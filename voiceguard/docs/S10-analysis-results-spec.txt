SECTION 1 — ARCHITECTURE SUMMARY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Data model (from src/types/index.ts):
  ScanResult {
    scan_id             string
    status              'pending' | 'processing' | 'completed' | 'failed'
    verdict             'human' | 'ai_generated' | 'uncertain' | null
    confidence          number (0–100)
    human_score         number (0–100)
    ai_score            number (0–100)
    inference_time_ms   number
    model_version       string
    segment_count       number
    frequency_heatmap   string | null   (URL to image, optional)
    file_name           string
    file_duration_seconds number
    created_at          string (ISO)
    share_token         string | null
    user_verdict        'human' | 'ai_generated' | 'uncertain' | null
  }

API surface (from src/services/api.ts):
  scanApi.status(scanId)              → { data: ScanResult }
  scanApi.delete(scanId)              → void
  scanApi.submitFeedback(scanId, v)   → void  (v: 'human'|'ai_generated'|'uncertain')
  scanApi.share(scanId)               → { share_url: string }

Three-state verdict thresholds:
  human        → human_score ≥ 85
  ai_generated → ai_score   ≥ 85
  uncertain    → everything else (scores between 15–84)

Design tokens (from tailwind.config.ts):
  Background  : #080810  (bg-bg-base)
  Surface     : #0E0E1A  (bg-bg-surface)
  Brand       : #7B6CEA  (text-brand, bg-brand)
  Human       : #32D583  (text-human, bg-human)
  AI          : #FF4F4F  (text-ai, bg-ai)
  Uncertain   : #F5A623  (text-uncertain, bg-uncertain)
  Text primary: #F0F0FF
  Text sec    : rgba(240,240,255,0.6)
  Text tert   : rgba(240,240,255,0.35)
  Border      : rgba(255,255,255,0.08)
  Glows       : shadow-glow-human, shadow-glow-ai, shadow-glow-brand
  Keyframe    : animate-confidence-fill (already in Tailwind config)

Reused components:
  AudioPlayer, WaveformVisualizer  ← src/pages/NewScan/components/
  Button, Badge, Skeleton          ← src/components/ui/
  PageContainer                    ← src/components/layout/
  Toaster (sonner)                 ← global in App.tsx

SECTION 2 — SCREEN STATES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

STATE A — LOADING SKELETON
  Triggered  : scanId present, API call in-flight (first load)
  Layout     : Same card structure as success, filled with Skeleton components
  Duration   : Until first API response resolves
  Skeleton areas:
    - VerdictHeroCard: 64×64 circle + two text bars (50%, 30%)
    - Gauge: 200×200 circle skeleton
    - ScoreBreakdownCard: 3 bar rows, each label + bar + percent
    - AudioInfoCard: 4 rows of metadata pairs
    - EvidenceCard: 1 heading + 3 text lines
    - SegmentTimeline: full-width bar skeleton
    - TechnicalDetailsCard: 4 text rows

STATE B — NOT FOUND (404)
  Triggered  : API returns 404 or scanId belongs to different user
  Layout     : Centered empty state, no AppShell chrome changes
  Content    :
    - Icon: Search (Lucide), 48×48, text-text-tertiary
    - Heading: "Result not found"
    - Body: "This scan doesn't exist or you don't have access to it."
    - CTA: Button → /history ("View your scans")
  No retry — 404 is permanent.

STATE C — STILL PROCESSING
  Triggered  : status === 'pending' || status === 'processing'
  Layout     : Centered card, no full-page content
  Content    :
    - Animated waveform pulse (reuse ProcessingAnimation)
    - Heading: "Analysis in progress"
    - Body: "Check back in a moment — results will appear here automatically."
    - Auto-refresh: poll every 3 seconds (separate from useScanPolling), navigate
      to same route (replace: true) when completed — triggers re-render
    - CTA: Link → /scan/processing?id={scanId} ("View processing status")
  Accessibility: role="status" aria-live="polite" on the auto-refresh container

STATE D — ANALYSIS FAILED
  Triggered  : status === 'failed'
  Layout     : Same as STATE B but with failure-specific copy
  Content    :
    - Icon: AlertOctagon, text-ai
    - Heading: "Analysis failed"
    - Body: "Something went wrong during processing. Try uploading again."
    - CTAs: "Try again" → /scan/new  |  "View history" → /history

STATE E — SUCCESS (main design)
  Triggered  : status === 'completed' && verdict !== null
  Full layout with all sections described in Section 3.

3.2 Confidence Gauge (SVG)
────────────────────────────────────────────────────────────────────────────────
Placement  : Right column of hero row (md+); below VerdictHeroCard on mobile
Size       : 200×200 viewBox, 180×180 rendered (mx-auto)

SVG structure:
  Background track arc:
    SVG arc, 270° sweep (starts at 135°, ends at 405° / sweeps clockwise)
    stroke: rgba(255,255,255,0.06), strokeWidth: 12, fill: none
    r = 72, cx = 100, cy = 100
    stroke-linecap: round

  Fill arc (animated):
    Same path, same r
    stroke: verdict color (human=#32D583, ai=#FF4F4F, uncertain=#F5A623)
    strokeDasharray: computed from circumference × 0.75 (270/360)
    strokeDashoffset: animated from full-offset to (1 - confidence/100) × totalDash
    Animation: CSS transition on stroke-dashoffset, 1.2s ease-out, delay 0.3s
    OR: use Framer Motion animate on a custom var

  Threshold markers (two tick marks on the arc):
    At 65% fill position  → tick at arc position for 65% of 270° sweep
    At 85% fill position  → tick at arc position for 85% of 270° sweep
    Each tick: short line segment (length 6px) perpendicular to arc, stroke rgba(255,255,255,0.2)
    Tooltip on hover: "Below 65%: unreliable" / "Above 85%: high confidence"

  Center text:
    Large number: "{confidence}" — text-3xl font-bold, verdict-colored, dy=-6
    Label: "confidence" — text-xs, text-text-tertiary, dy=16
    Animation: motion.span countUp from 0 to confidence over 1s, starts at 0.4s delay

  Screen reader:
    <title> element inside SVG: "Confidence gauge: {confidence}%"
    role="img" aria-labelledby="gauge-title" on the <svg>

3.5 EvidenceCard
────────────────────────────────────────────────────────────────────────────────
Purpose   : Plain-language explainability. No jargon. Helps users understand WHY.
Container : card-base rounded-xl p-5
Heading   : "What did the model detect?" — text-sm font-semibold text-text-secondary mb-3

Content is verdict-specific:

  HUMAN verdict:
    Lead: "The audio contains natural human voice characteristics."
    Details (bullet list, text-sm text-text-secondary, gap-2):
      • "Natural pitch variation and micro-tremors consistent with biological speech production."
      • "Breath patterns and pause timing match human conversational cadence."
      • "No spectral artifacts associated with neural vocoders or GAN-based synthesis."
    Footer note (text-xs text-text-tertiary italic):
      "The LCNN model analyzed {segment_count} overlapping 3-second segments."

  AI GENERATED verdict:
    Lead: "Synthetic audio signatures were detected across multiple segments."
    Details:
      • "Unnatural spectral smoothness inconsistent with human vocal tract resonance."
      • "Pitch stability deviations typical of neural text-to-speech or voice conversion."
      • "Phase inconsistencies across frequency bands suggest digital synthesis."
    Footer note: same as human, same format

  UNCERTAIN verdict:
    Lead: "The model could not make a high-confidence determination."
    Details:
      • "Scores fell within the 15–84% range where either classification has low reliability."
      • "This may occur with heavily compressed audio, background noise, or very short clips."
      • "Consider re-uploading with a longer, higher-quality recording for a clearer result."
    Guidance box (mt-3, bg-uncertain-muted border border-uncertain-border rounded-lg p-3):
      Icon: Info w-4 h-4 text-uncertain (inline, aria-hidden)
      Text: "An uncertain result does not mean the audio is safe or unsafe.
             It means our model needs more signal. Use your own judgment."
      text-xs text-uncertain/80

4.1 ShareDialog
────────────────────────────────────────────────────────────────────────────────
Trigger    : "Share" ActionBar button
Component  : shadcn/ui Dialog

Open sequence:
  1. If share_token exists on ScanResult: compute URL directly from token
     (https://voiceguard.app/r/{share_token})
  2. If share_token is null: call scanApi.share(scanId) → { share_url: string }
     Show loading spinner inside Dialog until resolved
  3. Cache share_url in local state (avoid repeated API calls on re-open)

Dialog content:
  Title    : "Share Result"
  Body     :
    Icon   : Link2, mx-auto, text-brand, w-10 h-10, mb-4
    Text   : "Anyone with this link can view the result (no login required)."
             text-sm text-text-secondary text-center mb-4
    URL field:
      Flex row: input (readOnly, bg-white/4, border-white/8, rounded-lg px-3 py-2 text-sm text-text-secondary flex-1)
      + Copy button (Button size="sm", Copy/Check icon)
      Copy behavior: navigator.clipboard.writeText(shareUrl) → icon → Check for 2s → Copy
      Accessible: button aria-label="Copy share link"
  Footer   :
    Close button (Button variant="ghost" fullWidth)

Error:
  If scanApi.share() fails: inline error inside Dialog
  "Could not generate share link. Please try again."
  + Retry button

4.2 DeleteDialog
────────────────────────────────────────────────────────────────────────────────
Trigger    : "Delete scan" item in ActionBar's DropdownMenu
Component  : shadcn/ui AlertDialog (not Dialog — semantic difference)

Content:
  Title    : "Delete this scan?"
  Body     : "This action cannot be undone. The scan result and all associated
              data will be permanently deleted."
             text-sm text-text-secondary
  Footer   :
    Cancel button : Button variant="secondary" → closes dialog
    Delete button : Button variant="destructive" ("Delete")
                    text-white bg-ai hover:bg-ai/80 focus-visible:ring-ai

Delete sequence:
  1. Click Delete → button shows loading spinner, both buttons disabled
  2. Call scanApi.delete(scanId)
  3. On success: toast.success("Scan deleted.") → navigate('/history', {replace:true})
  4. On error  : toast.error("Failed to delete scan. Please try again.")
                 Dialog remains open, buttons re-enabled

Accessibility:
  AlertDialog role="alertdialog" aria-labelledby aria-describedby (shadcn handles this)
  Focus trapped inside dialog
  Escape key closes (shadcn default)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

useScanResult(scanId: string)
────────────────────────────────────────────────────────────────────────────────
Returns: { state: ScanResultState }
Where ScanResultState = {
  status: 'loading' | 'not_found' | 'processing' | 'failed' | 'success'
  result: ScanResult | null
  error:  string | null
}

Behavior:
  - On mount: call scanApi.status(scanId)
  - 404 response → status: 'not_found'
  - 401/403 response → status: 'not_found' (same treatment, don't leak existence)
  - result.status === 'pending' | 'processing' → status: 'processing', start re-poll loop
  - result.status === 'failed' → status: 'failed'
  - result.status === 'completed' → status: 'success', result: data
  - Network error → status: 'failed', error: 'Network error. Please refresh.'

Re-poll loop (only when status: 'processing'):
  - Poll every 3 seconds using closure-based cancelled flag (same pattern as useScanPolling)
  - When completed or failed: stop polling, update state accordingly
  - Cleanup: clear timeout on unmount

NOTE on AudioPlayer in results:
  The ScanResult does NOT include an audio URL — audio is deleted within 60s of inference.
  Therefore, the AudioPlayer in the results screen will almost always show "unavailable."
  The AudioInfoCard should NOT attempt to fetch or display audio.
  The audio metadata (file_name, file_duration_seconds) is still shown.
  Remove the AudioPlayer section from the final implementation or show it as unavailable state only.
  Do NOT add API calls to retrieve audio — audio is not stored.

SECTION 10 — UX REVIEW FINDINGS + RESOLUTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

FINDING 1 — Audio file privacy vs AudioPlayer expectation
  Issue   : Users arriving from S09 may expect to hear their audio on the result
             screen. But audio is deleted within 60 seconds of inference.
  Risk    : Showing a broken AudioPlayer is confusing and damages trust.
  Resolution: Remove AudioPlayer from results screen entirely.
              Show file metadata only (name, duration, format).
              Add privacy badge: "Audio securely deleted after analysis."
              This is a feature (privacy-first), communicate it positively.

FINDING 2 — aria-live noise on automated states
  Issue   : STATE C (still processing) uses auto-poll every 3s. Adding aria-live
             to a countdown or "refreshing..." indicator would be extremely noisy.
  Resolution: Use role="status" aria-live="polite" ONLY on the state change message
              ("Analysis complete, loading results…"). Do NOT add aria-live to
              polling-related UI elements. The navigate() call is the accessibility
              "announcement" via route change.

FINDING 3 — Uncertain verdict needs action guidance, not just explanation
  Issue   : "Uncertain" is ambiguous. Users don't know what to do next.
  Resolution: EvidenceCard for uncertain verdict includes a "What to do" guidance
              box with: upload longer clip, improve audio quality, use your own judgment.
              FeedbackCard remains enabled (they can still submit their opinion).
              ActionBar always shows "New Scan" as first visible CTA.

FINDING 4 — Score bars need 85% threshold visual marker
  Issue   : Users don't know what score represents "high confidence." The 85%
             threshold is invisible without a marker.
  Resolution: Add a thin vertical tick at 85% position inside each score bar track.
              On hover: Tooltip "Above 85%: high confidence threshold"
              Also reflected in ConfidenceGauge threshold tick marks.

FINDING 5 — Feedback card placement
  Issue   : Placing feedback AFTER the action bar (below delete/share) means most
             users will never see it. Feedback before actions risks anchoring bias
             (user rates before reading evidence).
  Resolution: Feedback placed AFTER evidence and technical details, but BEFORE
              the action bar. User reads the full explanation, then rates, then acts.
              This order: Verdict → Evidence → Technical → Feedback → Actions.

FINDING 6 — Download Report is high-effort with unclear output
  Issue   : "Download Report" as a primary action implies a PDF or structured file.
             Implementing PDF generation in-browser (jsPDF, html2canvas) is heavy.
  Resolution: For MVP: "Download Report" generates a plain-text .txt file with
              verdict, scores, evidence text, metadata, and timestamp.
              Use Blob + URL.createObjectURL + anchor click — no external library needed.
              Label: "Download Report (.txt)" to set correct expectations.
              Future: upgrade to PDF.

FINDING 7 — Share link vs share_token lifecycle
  Issue   : share_token may be null initially. Calling share() on every result
             page load wastes an API call and creates tokens unnecessarily.
  Resolution: Only call scanApi.share(scanId) when user explicitly clicks "Share."
              Cache in component state. If user closes and reopens ShareDialog in
              same session, use cached URL. Never pre-fetch.

FINDING 8 — Segment timeline is misleading without per-segment scores
  Issue   : A timeline colored entirely in one verdict color implies we have
             per-segment data when we don't. Users may interpret color gradations
             that don't exist.
  Resolution: Use a stippled/gradient fill instead of solid color for the timeline bar.
              Label it: "Overall confidence projected across {n} segments"
              Add a note: "Per-segment breakdown coming soon."
              This communicates what we DO have (segment count) without implying more.
