CRITICAL ARCHITECTURE NOTE
--------------------------
There is NO JavaScript frontend. The UI is Gradio — a Python library that
renders a web interface server-side. "Frontend personalization" means modifying
gr.Interface / gr.Blocks parameters and Gradio's theming API, all in Python.

TWO DISTINCT DEPLOYMENT SURFACES
---------------------------------
Surface 1 — HuggingFace Spaces (Gradio demo)
  Entry point: app.py (root)
  Auto-deployed via: .github/workflows/sync_to_hf.yml on push to main

Surface 2 — Docker container (FastAPI REST API)
  Entry point: api/main.py
  Endpoint: POST /predict  ->  PredictionResponse(label, confidence, scores)
  Endpoint: GET  /health

HOW FRONTEND TALKS TO BACKEND
------------------------------
Gradio app: No HTTP call. run_inference() calls Python functions directly
  (predict(), load_model()). No API contract to break.

FastAPI app: Clients POST a raw audio file to /predict and receive:
  { "label": "bonafide|spoof", "confidence": 0.97,
    "scores": { "bonafide": 0.97, "spoof": 0.03 } }

    src/
    ├── models/
    │   ├── lcnn.py          <- LCNN architecture (Conv + MaxFeatureMap)
    │   ├── rawnet2.py       <- RawNet2 architecture

    │   └── predict.py       <- load_model(), predict() — core inference

    ├── main.py              <- FastAPI routes (/health, /predict)
    └── schemas.py           <- PredictionResponse, Scores (Pydantic)

    configs/
    ├── lcnn.yaml            <- model hyperparameters
    └── rawnet2.yaml

    pyproject.toml           <- package name and dependencies
    Dockerfile               <- container spec
    requirements.txt         <- pinned deps for HF Spaces

WHY THESE ARE OFF-LIMITS:
- api/schemas.py defines the JSON contract. Any field rename breaks clients.
- src/inference/predict.py returns {"label","confidence","scores"}.
  The Gradio UI destructures this dict directly — change it and both
  surfaces break.
- configs/ values feed into model initialization; wrong values = wrong
  predictions.

STEP 2: Rebrand the Gradio interface
--------------------------------------
Replace gr.Interface(...) with gr.Blocks() for more control.
The run_inference function signature is UNCHANGED.

    # app.py — replace the demo = gr.Interface(...) block with:

    import gradio as gr

    MY_THEME = gr.themes.Soft(
        primary_hue="violet",       # your brand color
        secondary_hue="slate",
        neutral_hue="slate",
        font=gr.themes.GoogleFont("Inter"),
        radius_size="md",
    )

    with gr.Blocks(
        theme=MY_THEME,
        title="VoiceGuard — AI Speech Authenticator",   # browser tab title
        css="""
            .gradio-container { max-width: 860px !important; margin: auto; }
            footer { display: none !important; }        /* hide Gradio branding */
        """,
    ) as demo:
        gr.Markdown("""
        # VoiceGuard
        **Detect AI-generated speech in seconds.**
        Upload any audio clip — the model highlights exactly which
        frequencies gave it away.
        """)

        with gr.Row():
            audio_in = gr.Audio(
                type="filepath",
                label="Upload audio (.wav · .flac · .mp3)"
            )

        with gr.Row():
            run_btn = gr.Button("Analyze", variant="primary")

        with gr.Row():
            result_box   = gr.Textbox(label="Verdict")
            confidence_n = gr.Number(label="Confidence")

        plot_out = gr.Plot(label="Spectrogram + Model Attention (Grad-CAM)")

        run_btn.click(
            fn=run_inference,
            inputs=audio_in,
            outputs=[result_box, confidence_n, plot_out],
        )

    if __name__ == "__main__":
        demo.launch()

KEY CONSTRAINT: fn=run_inference stays exactly the same. Its inputs and
outputs (3 values: label str, confidence float, matplotlib fig) are unchanged.
You are only rewiring the widgets around the same function.

    # Option A: External CDN

             style="margin-bottom:8px;">')

    # Option B: Embedded base64 (no external dependency)
    import base64, pathlib
    logo_b64 = base64.b64encode(
        pathlib.Path("assets/logo.png").read_bytes()

OPTION A: HuggingFace Spaces (recommended — zero infra, free tier)
--------------------------------------------------------------------
!! CRITICAL: Update the CI/CD workflow BEFORE first push.

    # .github/workflows/sync_to_hf.yml — change repo_id only

    - name: Push to HF Space
      env:
        HF_TOKEN: ${{ secrets.HF_TOKEN }}
      run: |
        python - <<'EOF'
        import os
        from huggingface_hub import HfApi

        api = HfApi(token=os.environ["HF_TOKEN"])
        api.upload_folder(
            folder_path=".",
            repo_id="YOUR_HF_USERNAME/your-space-name",   # <- CHANGE THIS
            repo_type="space",
            ignore_patterns=[
                ".git*", "checkpoints/", "notebooks/",
                "runs/", ".venv/", "__pycache__/",
                "*.pyc", "*.egg-info/", ".claude/",
            ],
        )
        EOF

Add your HF token as a GitHub secret:
  GitHub repo -> Settings -> Secrets -> Actions -> New secret
  Name: HF_TOKEN
  Value: your HF write token (from https://huggingface.co/settings/tokens)

Every push to main auto-deploys to your Space.

For a custom domain (HF Spaces Pro plan):
  HF Spaces -> Settings -> Custom Domains -> add yourdomain.com


OPTION B: Docker on Render / Railway (FastAPI only)
-----------------------------------------------------
    # Build and push
    docker build -t your-app .
    docker tag your-app YOUR_DOCKER_USERNAME/your-app:latest
    docker push YOUR_DOCKER_USERNAME/your-app:latest

    Render deployment steps:
    1. New Web Service -> connect your GitHub repo
    2. Environment: Docker
    3. Port: 8000
    4. Add a persistent disk at /app/checkpoints and upload best.pt once

    Fly.io alternative (better cold-start than Render free tier):
    fly launch --dockerfile Dockerfile --port 8000
    fly volumes create checkpoints --size 1
    fly deploy


OPTION C: Vercel / Netlify
---------------------------
NOT APPLICABLE. These are static-site / serverless-JS platforms.
FastAPI + PyTorch does not run on them. Use HF Spaces, Render, Railway,
or Fly.io instead.
